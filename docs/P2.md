# P2: later

Larger features and long-running verification. Not planned for 1.5.4 or 1.6. Revisit after the
launch based on what users ask for.

Status: `[ ]` open, `[~]` in progress, `[x]` done.

---

## P2-01 Local transcription engine `[ ]`

`meeting_transcribe` uploads audio to Groq. Add an optional local engine (Whisper through a local
binary or `whisper.cpp`) so audio never leaves the machine. Needs a decision on model download
size and a clear "first run downloads N MB" message.

## P2-02 Real macOS verification `[ ]`

CI covers macOS, but nobody has run the server by hand on a Mac. Find a tester, run the P0-11
checklist, and record it.

## P2-03 Nightly live smoke tests `[ ]`

A scheduled workflow that uses dedicated test accounts and secrets to call each integration once.
It catches API drift (a changed field, a retired endpoint) before users do. Failures open an
issue.

## P2-04 BoundaryAttest to production grade `[ ]`

It is a proof of concept today (three workflow tools, a key file you manage). Needs key storage,
rotation, revocation, a trust registry and an optional KMS or HSM backend. Only worth doing if
users ask for signed receipts.

## P2-05 Sync between machines `[ ]`

Pipeline, meetings and reminders live in one local database. Options: an encrypted export and
import, or a file-based sync folder. Needs a conflict policy. Do not build a cloud service for
this inside the open-source server. That belongs to the hosted product.

## P2-06 Soak and performance testing `[ ]`

- 24-hour session with periodic calls: memory growth, open handles, pool leaks
- Cold start time and `tools/list` latency with all packs loaded
- Large inputs: a 100 MB transcript, a repository with 100,000 files
- Publish the numbers in the docs

## P2-07 Fuzzing `[ ]`

Property-based and mutation tests for the argument parsers, the redactor, the path guard and the
URL guard. Run in CI on a schedule.

## P2-08 Supply-chain extras `[ ]`

Signed git tags, a software bill of materials published with each release, a license check on
every dependency, and a documented process for revoking a bad release (`npm deprecate`, advisory,
changelog note).

## P2-09 Enterprise features `[ ]`

- Policy file with an allowlist and denylist of tools per project
- Audit log export (JSON lines to a file or a syslog target)
- A "read-only mode" switch that removes every non-`READ` tool
- Per-project workspace profiles

## P2-10 More directory listings `[ ]`

Smithery needs an `.mcpb` bundle. Revisit PulseMCP, mcp.so and `awesome-mcp-servers` when their
queues or fees change.

## P2-11 Keyword volume `[ ]`

Keyword ideas come from search autocomplete and carry no volume. Add an optional provider with a
free tier, behind a key, and keep the keyless path as it is.

## P2-12 Outreach channels `[ ]`

Out of scope for now: LinkedIn, X and WhatsApp (terms of service and account risk). Email goes
through Gmail.

## Out of scope

Azure, GCP and AWS SDK tools. Terraform covers provisioning. Stripe and Discord packs exist in
the code but are not documented or promoted.
